# weir

設定に書かれた規則だけで、コミットと push を止める門。

`git commit` の代わりに `weir commit` を、`git push` の代わりに `weir push` を呼びます。
weir は自分の規則を1つも持ちません。何を止めるかは、あなたが `~/.weir/config.toml` と
`~/.weir/denylist` に書いたものだけで決まります。バイナリの中に既定の規則は入っていません。

## 何をするか

- 登録したリポジトリでだけ、コミットと push を実行する。
- **実行する前に、そこで外へ出るものを規則と照合する。** `block` の規則に当たれば実行しない。
  `warn` の規則に当たれば、場所を示して続行する。
- リポジトリは**名前**でしか指せない。作業ディレクトリからも、打たれたコマンドからも推測しない。
- 設定が読めなければ、実行しない。壊れた設定を「規則が0件」とは読まない。
- **規則が0件なら、実行はするが、毎回そう言う。** 黙って通すと、何も書いていないことに
  気づかないまま、守られているつもりになります。
- **拒否しても、一致した中身は出さない。** どこで当たったかと、どの規則が当たったか（設定の
  どの行か）だけを言います。中身を書き出したら、出さないために止めた意味がありません。

## 何をしないか

- **手元の履歴操作は止めない**（`tag` / `reset --hard` / `rebase`）。やり直せる操作まで止めると、
  素の git を使う場面で邪魔になる。止めるのは、外に出たら取り返せない commit と push だけ。
- **エージェントに素の git を使わせるかどうかは決めない**。それはそのエージェントの設定の話で、
  weir の責務ではない。weir は git の代わりに呼ぶ門であって、コマンドの監視役ではない。
- **設定ファイルを書き換えから守らない**。weir はエージェントと同じユーザー権限で動くので、
  weir 側で書き換えを止めることは成立しない。成立しない防御は持たない。

## 入れる

git が要ります。weir は git をプログラムとして呼びます。

### Homebrew

```sh
brew install ShiroDoromoto/weir/weir
```

### インストールスクリプト

```sh
curl -fsSL https://github.com/ShiroDoromoto/weir/releases/latest/download/install.sh | sh
```

### Go

```sh
go install github.com/ShiroDoromoto/weir/cmd/weir@latest
```

## 始める

### 1. 雛形を作る

```sh
weir init
```

`~/.weir/config.toml` と `~/.weir/denylist` を、**無いときだけ**作ります。既にあるものには
触りません。何度打っても結果は変わりません。

雛形はどの行もコメントアウトしてあります。有効になるのは、あなたが `#` を外した行だけです。

### 2. リポジトリを登録する

`~/.weir/config.toml` に書きます。

```toml
[repos.weir]
path = "/Users/あなた/develop/weir"

[repos.notes]
path = "/Users/あなた/develop/notes"
```

- `path` は**絶対パス**で書きます。`~` も環境変数も展開しません。
- **worktree ではなく本体**のパスを書きます。worktree から打っても、weir は本体を見つけます。

登録しただけでは何も止まりません。何を止めるかは[規則を書く](#規則を書く)を見てください。

### 3. 検査する

```sh
weir config check
```

設定を頭から終わりまで読んで、見つかった問題を全部並べます。1件でもあれば非ゼロで終わります。
どのリポジトリに何件の規則が効くかも並べるので、何と照合されるのかを設定を開かずに確かめられます。
規則が0件のリポジトリには `⚠ 何も止まりません` が付きます（0件は問題ではないので、終了コードは
0 のままです）。

```
設定: /Users/あなた/.weir/config.toml
語の一覧: /Users/あなた/.weir/denylist

  既定の規則 2件（すべてのリポジトリに効きます）

  notes  /Users/あなた/develop/notes
         規則 2件（既定 2 + このリポジトリ 0）
         ✗ そのパスがありません
  weir   /Users/あなた/develop/weir
         規則 2件（既定 2 + このリポジトリ 0）

問題が1件あります。/Users/あなた/.weir/config.toml を直してください。
```

## コマンド

| コマンド | すること |
| --- | --- |
| `weir init` | 設定の雛形を作る（無いときだけ） |
| `weir config check` | 設定を検査して報告する |
| `weir repos` | 登録されているリポジトリを一覧する |
| `weir commit` | 登録したリポジトリでコミットする |
| `weir push` | 登録したリポジトリでプッシュする |
| `weir version` | 版を表示する |
| `weir help` | 使い方を表示する |

### weir commit

```sh
weir commit --repo <リポジトリ名> --message "変更の説明" [--all]
```

- `--repo` — 対象のリポジトリ名（`~/.weir/config.toml` の `[repos.<名前>]`）
- `--message` — コミットメッセージ
- `--all` — ステージされていない変更（追跡済みのファイル）も対象にする

git の `-m` / `-a` は取りません。名前を省くこともできません。どのリポジトリで何をしたのかが、
打った行だけで答えられる形にしてあります。

### weir push

```sh
weir push --repo <リポジトリ名>
```

送り先は指定しません。素の git と同じく、いまのブランチの upstream に送ります。weir と素の
git が「どこへ送ったか」で食い違わないようにするためです。

upstream が無いブランチでは**送りません**。何が送られるのかが決まらないので、判定できません。
先に upstream を決めてください（既にリモートに枝があるなら、送らずに
`git branch --set-upstream-to=<リモート>/<ブランチ名>` で決められます）。

### weir repos

```sh
weir repos
```

登録されているリポジトリと、そのパスを並べます。設定ファイルを開かずに、weir が何を対象に
できるかを確かめられます。

## 設定

| 場所 | 中身 |
| --- | --- |
| `~/.weir/config.toml` | リポジトリの登録と、照合の規則 |
| `~/.weir/denylist` | 拒否する語の一覧（1行1語。`#` で始まる行と空行は無視） |

置き場所は変えられません。環境変数でもオプションでも動かせないので、weir が何を読んだかは
常に1つに定まります。

weir を打つたびに、両方を読みます。`denylist` が無い・読めない場合は実行しません。無いものを
「語が0件」とは読みません。

### 規則を書く

規則の型は3つです。**どこに書くかで型が決まります。**

| 型 | 書く場所 | 当てる先 | 書き方 |
| --- | --- | --- | --- |
| `literal` | `~/.weir/denylist` | メッセージ、追加される行 | 語をそのまま。1行1語 |
| `pattern` | `config.toml` の `[[rules]]` | メッセージ、追加される行 | Go の正規表現（RE2） |
| `path` | `config.toml` の `[[rules]]` | 変更されるファイルのパス | glob |

**型は当てる先を跨ぎません。** `pattern` の規則はパスに当たりませんし、`path` の規則は追加行の
中身に当たりません。パスらしき文字列が差分の中にあっても、そのファイルを変更したことにはならない
からです。

#### 語 — `~/.weir/denylist`

```
山田太郎
acme-corp
```

- 1行1語。`#` で始まる行と空行は読み飛ばします。
- **大小文字は区別せず、部分一致**で照合します。語境界は見ません。実名は活用した形や、
  他の語と連結した形で現れるので、語境界で切ると拾えません。
- **ここに書いた語は必ず拒否します（`block`）。`warn` にはできません。** この一覧は「拒否する語」
  そのもので、判定を書く欄がありません。
- 設定ファイルには書けません。`type = "literal"` は読み込みの時点で拒否します。設定を人に見せる
  ときに、実名の一覧まで一緒に出さずに済ませるためです。

#### `pattern` と `path` — `~/.weir/config.toml`

```toml
[[rules]]
type = "pattern"
value = "AKIA[0-9A-Z]{16}"
action = "block"

[[rules]]
type = "path"
value = "**/.env"
action = "block"
```

`type` / `value` / `action` の3つとも必須です。**weir は省かれた項目を埋めません。** 埋めると、
設定を読んでも何が効くのかが答えられなくなります。

**`pattern`** — Go 標準の `regexp`（RE2）です。後方参照と先読みは使えません。コミットのたびに
走るので、入力次第で止まらなくなる実装は使いません。

**`path`** — glob です。[doublestar](https://github.com/bmatcuk/doublestar) の方言で、`.gitignore`
やエディタと同じ書き方です。

| 書き方 | 当たるもの |
| --- | --- |
| `secrets/*.pem` | `secrets/` **直下**の `.pem` |
| `secrets/**` | `secrets/` 配下すべて（階層を跨ぐ） |
| `**/.env` | どの階層の `.env` にも |
| `*.{pem,key}` | 最上位の `.pem` と `.key` |

`*` は `/` を跨ぎません。`**` は跨ぎます。**階層の深さは規則を書いた時点では分かりません** ——
直下の `.env` を止めるつもりで `*.env` と書いた後にリポジトリが `apps/api/` へ割れると、
`apps/api/.env` に当たりません。跨がせたいなら `**` を書いてください。

#### `block` と `warn`

| 判定 | すること |
| --- | --- |
| `block` | 拒否する。コミットも push もしない |
| `warn` | 拒否しない。一致した場所を示して続行する |

**推定に頼る規則は `warn` で書いてください。** 実名らしき形、帰属表記、それらしいキーの形など、
「たぶんそうだろう」で当てる規則は必ず誤検知します。誤検知で拒否すると、やがて拒否そのものが
無視されるようになります。止まるべきときに止まらなくなるのは、そのときです。

確実に外れないもの（発行済みのキーの形、書いてはいけない実名）は `block`。それ以外は `warn` から
始めて、外れないと分かってから `block` に上げるのが確実です。

#### 既定と、リポジトリごと

```toml
# すべてのリポジトリに効く
[[rules]]
type = "path"
value = "**/.env"
action = "block"

[repos.notes]
path = "/Users/あなた/develop/notes"

# notes にだけ足す
[[repos.notes.rules]]
type = "path"
value = "drafts/**"
action = "warn"
```

リポジトリごとの規則は既定に**追加**されます。**既定を無効化する書き方はありません。** リポジトリ
側の指定が締める方向にしか効かないので、既定を読めば「最低でもこれは効く」と言い切れます。

何件効いているかは `weir config check` が並べます。

### 何と照合するか

| | `weir commit` | `weir push` |
| --- | --- | --- |
| 見るもの | これからコミットされるもの | upstream にまだ無いコミット |
| 文字列 | コミットメッセージ、追加される行 | 各コミットのメッセージ、各コミットの追加行 |
| パス | 変更されるファイルのパス | 送られるコミットが変更したパス |

- **消される行は見ません。** 名前を消すコミットこそが直しなので、消した中身で拒否しません。
- **push は、後のコミットが消した中身も見ます。** 履歴に残ったままリモートへ出るからです。
- **push は、既に upstream にあるコミットは見ません。** 送られないものを拒否の材料にしません。
- upstream が無いブランチでは、何が送られるのか決まらないので **push しません**。

## 終了コード

| 値 | 意味 |
| --- | --- |
| 0 | 通した |
| 1 | `block` の規則に一致して止めた、設定が読めない、検査で問題が見つかった、または git が失敗した |
| 2 | 打ち方が違う（知らないコマンド、足りない・余分な引数、登録されていないリポジトリ名） |

出力を読まなくても、終了コードだけで通ったかどうかが分かります。

## 開発

```sh
make check    # gofmt / go vet / go test / actionlint
make build    # bin/weir を焼く
```

CI も `make check` を呼びます。手元と CI で別のものは回しません。
